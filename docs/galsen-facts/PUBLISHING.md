# Publishing workflow

## 1. Choose the question

Start with a reader question, not with a dataset simply because it exists.

## 2. Source check

Record the source owner, document or dataset URL, covered period, retrieval date, reuse constraints and obvious limitations.

## 3. Prepare the material

Keep transformations reproducible. Small cleaned files can live under `src/data/galsen-facts/`; scripts belong under `scripts/galsen-facts/`.

## 4. Build the story

Draft the explanation first, then choose the minimum number of charts or infographics needed to support it.

## 5. Review

Before publishing, verify numbers against the source, labels, periods, units, links, mobile rendering and the distinction between fact and interpretation.

## 6. Publish inside M221Tech

The hub at `/galsen-facts/` remains the entry point. New explorations should inherit the shared mark, source treatment and metadata rather than creating one-off visual systems.

## 7. Reassess product shape

Consider a standalone data platform only when users repeatedly need cross-article search, filters, reusable datasets, recurring updates or dashboards. Until then, articles plus focused interactive graphics are the default.
